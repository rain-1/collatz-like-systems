# div235_7n1_s11

## FATE
Exact simulation: 11 -> 78 -> 39 -> 13 -> 92 -> 46 -> 23 -> 162 -> 81 -> 27 -> 9 -> 3 -> 1 -> 8 -> 4 -> 2 -> 1. That is preperiod 12 and period 4, and 11 is not on the cycle (checks/div235_7n1_s11.py).

## GLOBAL: what was tried
* Accelerated form: for n coprime to 30, n -> (7n+1)/(2^a 3^b 5^c).
* Heuristic drift: ln7 - 2ln2 - (3/4)ln3 - (5/16)ln5 = -0.77 < 0. This predicts convergence but is not a proof.
* There is no invariant residue class, so congruence and automaton tools have nothing to work with. The stopping time is unbounded (220 steps below 10^6), so no finite descent table can cover it.
* Simulation (exploratory run to 10^6; checks re-run to 2*10^5): every n <= 10^6 descends or closes a cycle, and the only cycle found is {1,8,4,2}.
* This is a convergence problem of 3x+1 type for a generalized Collatz map. No reduction to a solved case was found.

## Referee
Verdict: FATE confirmed (tier 0, by exact simulation to the cycle). GLOBAL open-agreed (tier 5).
I re-ran the check and also surveyed every n <= 10^6 myself. My maximum stopping times match the stated ones (5n+1: 140 at n=986231; 7n+1 with /2,/3,/5: 220 at n=468109; 7n+1 with /2,/3: 9767 at n=966791, reaching 163 bits; the 34-cycle with min 19 and max 20168 is confirmed). The drift values are correct: E[v2] = 2, and the probabilities that 3 and 5 divide the image are 1/2 and 1/4.
Why tiers 1-3 fail: on the 2-adic and 3-adic side, the growth branch (an image with v2 = 1 and no other small-prime factor) is an affine bijection between residue classes. So any finite pattern of growth steps is realised by a nonempty residue class, by CRT. That makes stopping times unbounded and rules out any finite descent table or congruence-closed trap. I could find no conjugacy, automaton or coset invariant. Proving convergence would need control over orbit statistics of the kind that is missing for 3x+1 itself, so I regard this as genuinely of Collatz difficulty. It is not literally a named problem.
